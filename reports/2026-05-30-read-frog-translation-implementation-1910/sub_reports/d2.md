# d2. 文本抽取与上下文构造

## 本维度要回答的问题

- 待翻译内容来自用户选区、DOM、页面段落还是其它数据结构？
- 系统如何分段、过滤、保留上下文或避免重复翻译？
- 输入构造对翻译质量、性能和隐私有什么影响？

## 搜索覆盖情况

本维度完成两轮以上源码定位：

- 第一轮沿 d1 入口追踪：页面翻译从 `PageTranslationManager` 进入 DOM walk，节点翻译从鼠标坐标进入 block node，选区翻译从 `window.getSelection()` 进入 toolbar state。
- 第二轮按输入构造关键词追踪：`walkAndLabelElement`、`extractTextContent`、`buildContextSnapshot`、`prepareTranslationText`、`getOrCreateWebPageContext`、`shouldFilterSmallParagraph`。
- 原始核验覆盖 DOM traversal/filter/find、selection utils、translation variants、webpage context 和配置 schema。

停止理由：页面翻译、节点翻译、选区翻译、translation hub 四种主要输入路径都已定位；后续搜索主要进入 provider 请求层，转交 d3。

## 关键发现

1. read-frog 至少有四类翻译输入来源：
   - 页面翻译：来自当前网页 DOM 中被 walk 标记的段落/inline 节点。
   - 节点翻译：来自鼠标坐标命中的最近 block ancestor。
   - 选区翻译：来自浏览器 Selection 的文本和 range 快照。
   - translation hub / 输入框翻译 / 字幕翻译：来自用户输入、编辑器输入或字幕处理器的纯文本，这些路径复用底层 `executeTranslate`。

2. 页面翻译不是一次性把整页文本扔给模型。它先给 DOM 节点打标签，再用 IntersectionObserver 对进入视口的 top-level paragraph 做懒翻译。新增 DOM 或隐藏元素变为可见时，会重新观察并触发翻译。

3. 分段策略以 DOM 结构为主：`walkAndLabelElement` 标记 paragraph、block、inline；`translation-walker` 对 paragraph 下的 block 节点递归，对连续 inline/text 节点合并翻译。这让它能在保持页面结构的同时减少碎片化请求。

4. 选区翻译会保留上下文，但不是简单发送整页。`readSelectionSnapshot` 保存选中文本和 range；`buildContextSnapshot` 找到选区跨越的段落 owner，拼出 `paragraphs` 和 `text`。同时，AI 上下文感知模式还可抽取网页标题和正文摘要。

5. 网页上下文用于 LLM prompt，不用于非 LLM 翻译服务。上下文生成路径是：content script 克隆当前 HTML 文档，Defuddle 提取 Markdown 内容，截断为最多 2000 字符；如开启摘要，则通过 background 队列生成 2-3 句摘要并缓存。

## 分析

read-frog 的输入构造是“局部文本 + 可选全局上下文”的设计。

页面翻译走局部 DOM 段落，优点是请求粒度小、可懒加载、可缓存，并能在复杂网页中局部失败局部展示错误；代价是跨段落语义可能不足，所以它额外提供 AI content-aware 上下文来补强术语和语境。

选区翻译更适合即时查询：它保留用户真正选中的文本，同时把选区所在段落作为上下文快照。LLM provider 分支还可把网页标题、正文和摘要放入 prompt；标准 provider 分支则通过 `translateTextCore` 复用同一底层请求逻辑。

节点翻译介于两者之间：它从坐标命中一个 block node，再复用 DOM walk 和 translate walked element 逻辑，因此更像“对单个页面节点做页面翻译”。

过滤策略主要服务性能与可读性：隐藏元素、无意义标签、notranslate、纯数字、小段落、目标语言或 skip language 都可能被跳过。重复翻译由 wrapper 检查、`translatingNodes` WeakSet、cache hash 三层共同减少。

## 对终稿的贡献

本维度提供终稿中的“输入构造”主线：

| 输入路径 | 文本来源 | 上下文来源 | 关键文件 |
|---|---|---|---|
| 页面翻译 | DOM paragraph / inline group | 可选网页标题、正文、摘要 | `page-translation.ts`, `traversal.ts`, `translation-walker.ts` |
| 节点翻译 | 鼠标坐标命中的 block node | 当前页面配置与可选网页上下文 | `node-translation.ts`, `find.ts`, `node-manipulation.ts` |
| 选区翻译 | `Selection.toString()` + range 快照 | 选区所在段落、可选网页标题/正文/摘要 | `selection.content/utils.ts`, `SelectionTranslationProvider` |
| translation hub | 用户输入文本 | 基础语言配置；未走页面 DOM 上下文 | `translation-hub/components/translation-card.tsx` |

## 不确定性与空白

- Defuddle 对不同网页的抽取质量取决于页面结构；源码有 fallback，但没有在本研究中实际运行跨站点样本测试。
- 页面翻译的“主内容范围”由配置和 DOM 规则决定，复杂网页可能仍会漏翻或误翻。
- 选区上下文基于段落 owner 推断，跨 shadow DOM、复杂 selection 或 editable 区域场景虽有处理，但实际兼容性未做动态浏览器验证。
